# 镜像能力 (Image Capabilities)

镜像管理是 Crater 平台的核心功能之一，负责为 AI 训练与在线开发提供标准化的运行环境，并支持环境的持久化与多架构分发。

本文档是《Crater 平台系统能力与功能模块说明》的一个章节。

**解决的问题**：AI 开发需要各种深度学习框架和工具链环境（PyTorch、TensorFlow、CUDA 版本等），手动配置环境耗时且容易出错。

### 系统支持的能力

| 能力维度 | 说明 |
| :--- | :--- |
| 私有化部署镜像仓库 | 深度集成 Harbor 私有仓库，支持多项目管理、镜像标签浏览及按名称搜索 |
| 镜像导入 | 支持从 NVIDIA NGC 等官方镜像仓异步拉取镜像并导入平台私有仓库 |
| 平台内镜像构建 | 支持 Dockerfile、envd 以及基于 Buildkit 的异步构建等多种方式，提供实时构建日志流 |
| 多架构构建 | 支持在同一构建任务中产出 AMD64 和 ARM64 架构的镜像，适配异构 CPU 节点 |
| 镜像上传 | 支持用户通过标准 `docker push` 命令将本地构建的镜像直接推送到平台集成的 Harbor 仓库 |
| 镜像分享 | 支持基于账户（Account）或指定用户维度的权限控制，实现镜像在团队内或特定成员间的共享与隔离 |
| 环境快照/持久化 | 支持将运行中的 Jupyter/WebIDE 容器状态保存为新镜像，实现开发环境的即时沉淀 |

### 典型场景

- 研发人员在 Jupyter Lab 中通过 pip 安装复杂依赖并调试成功后，通过环境快照一键保存为新镜像，并分享给同组其他成员，确保整个团队在完全一致的环境下协作。
- 算法工程师编写好 build.envd 配置文件，利用平台的多架构构建能力，一次性产出适配 AMD64 和 ARM64 CPU 架构的镜像，实现模型在不同硬件节点上的无缝部署。
- 管理员通过镜像导入功能，将 NVIDIA NGC 等官方镜像仓中的热门基础镜像异步拉取到内网 Harbor 仓库，解决集群节点拉取公网大镜像慢、不稳定的问题。
- 在项目上线阶段，DevOps 工程师通过提交 Dockerfile 触发平台的 Buildkit 异步构建，在获得实时构建日志的同时，利用缓存复用能力快速产出生产级精简镜像。

### 私有化部署镜像仓库
平台深度集成 Harbor 作为底层存储引擎，为用户提供企业级的镜像托管服务。通过 Portal 界面，用户可以直观地管理不同项目下的镜像资源，查看镜像层级信息及历史标签，确保环境资产的安全与可控。

### 镜像导入
针对 AI 研发中常用的基础环境，平台支持从 NVIDIA NGC 等官方镜像仓库异步导入镜像。用户只需要在平台中输入镜像的 url，将会由 Crater 在后台完成镜像的拉取和缓存，用户可以在启动任务时直接选择这些镜像使用。

### 平台内镜像构建
Crater 提供了一套云原生的构建流水线，支持从标准 Dockerfile 到 AI 友好的 envd 等多种定义方式。构建任务在集群内异步执行，用户可实时追踪构建日志。通过集成 Buildkit，平台能够有效利用层缓存，显著缩短重复构建的时间。

### 多架构构建
针对集群中可能存在的异构 CPU 节点（如传统的 x86 节点与国产 ARM 节点），平台支持在单次构建任务中同时产出 AMD64 和 ARM64 架构的镜像。这确保了同一套算法代码在不同架构的计算节点上都能拥有完全一致的运行环境。

### 镜像上传
除了平台内构建，用户也可以利用本地成熟的开发环境，通过标准的 `docker push` 流程将镜像直接推送到平台集成的 Harbor 仓库。平台会自动识别新上传的镜像并将其纳入统一的管理与分发体系。

### 镜像分享
为了促进团队协作，Crater 提供了灵活的镜像分享机制。镜像所有者可以将特定的环境镜像授权给整个账户（团队）使用，或精确指定特定的平台用户。这种基于角色的访问控制（RBAC）确保了资产在安全的前提下高效流转。

### 环境快照/持久化
环境快照是 Crater 为交互式开发设计的特色功能。当研发人员在 Jupyter Lab 或 WebIDE 中完成复杂的依赖安装与环境调试后，可以随时将当前运行中的容器“冻结”并保存为新的镜像版本。这种方式极大地简化了环境沉淀的成本，使开发成果可以立即转化为可分发的生产环境。
