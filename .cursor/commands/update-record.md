# 创建更新记录

请在文档的更新记录章节中添加一项新记录。

## 🎯 输入要求
- 用户必须提供 **commit 链接**（GitHub/GitLab 链接）。
- 如果用户未提供 commit 链接，**请不要生成内容**，而是礼貌地要求用户提供链接。

## 📌 Commit 链接的用途
- Commit 链接**仅作为时间戳锚点**：从中提取日期、标题和短哈希，用于格式化更新记录。
- **不需要**分析 commit 的具体改动，也**不需要** commit 内容与文档更新主题相关。
- 更新记录的正文**只描述文档本身**在这次编辑中发生了什么变化。

## 🛠 执行步骤
1. **解析 Commit 信息**：
   - 从链接提取日期、commit 标题和短哈希（用作记录元数据，不作内容依据）。
2. **生成深度总结**：
   - 描述**文档本身**的更新（如：新增了哪些流程图、完善了哪些架构细节、修正了哪些过时描述），而不是代码修复或重构。
   - 避免过于细节的内容（如表格逐列解释），侧重于流程、依赖、设计动机。
   - 在详细描述前，先用一句话讲清楚这次更新的核心内容。
   - 新的更新记录应该出现在之前的更新记录上方。
   - 更新记录应该添加到文档的上方，作为第一个二级标题。
3. **格式化输出**：
   ```markdown
   > **YYYY-MM-DD** | [commit title](commit_link) | `short_hash`
   > [总结内容...]
   ```

## 🔗 链接规范
- 可以使用 `[[文件名#标题]]` 语法引用本项目内的其他文档。

## 📝 示例
> **2025-12-24** | [chore: format translation in pre-commit hook (#315)](https://github.com/raids-lab/crater/commit/518c88705ec7462f6c5d06d24a7aa70d7607f8b0) | `518c887`  
> 总结当前系统的三种认证方式（Normal、ACT-LDAP、ACT-API）的完整流程，包括用户创建、状态管理、权限分配和外部服务依赖关系。补充 LDAP 请求时机和数据说明、密码存储策略、ACT-API 数据库更新机制，明确 ACT-LDAP 仅用于密码验证，ACT-API 通过 OpenAPI 服务获取信息而非直接调用 LDAP。
