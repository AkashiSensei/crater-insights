# crater-cli 相关的需求与 idea

## 需求

通过命令行，绕开前端直接使用 crater。

## 想法

实现上应该类似于 `kubectl`。

需要考虑版本兼容性，比如保证一个大版本内 crater 和 crater-cli 是兼容的，或者至少向后兼容几个小版本。

## crater-cli 与 AI MCP

在决定是让 AI 使用 **命令行工具 (CLI)** 还是直接使用 **RESTful API** 时，核心在于权衡 **“认证/逻辑的封装性”**、**“数据交互的稳定性”** 以及 **“工程演进的维护成本”**。

### 1. 方案 A：让 AI 调用命令行工具 (CLI)

**实现逻辑**：MCP 作为一个简单的“Shell 包装器”，直接运行 `crater get pods`。

- **优势 (Pros)**：
  - **认证零成本 (Native Auth)**：CLI 自身维护登录状态（如 `~/.crater/config`）。MCP 调用 CLI 时，身份认证是“自动”完成的，无需在 MCP 中重写解析 Token 的逻辑。
  - **业务逻辑高度封装 (Porcelain)**：CLI 已经把“多步 API 调用”封装成了“一个命令”，AI 直接调用高层指令，逻辑极简。
  - **本地版本锁定 (Local Alignment)**：MCP 的能力与**本地二进制版本**强绑定。本地装了哪个版本，AI 用的就是哪个版本，行为完全确定。
  - **环境一致性**：人类用户怎么用，AI 就怎么用，便于纠错。

- **劣势 (Cons)**：
  - **“交互式”瓶颈**：人类 CLI 经常有 `Confirm [y/n]` 或 `Password` 输入提示，AI 在非交互环境下无法响应，会导致任务挂起。必须专门提供 `--yes` 或非交互模式。
  - **版本分发成本极高**：若后端升级而本地 CLI 未升级，AI 可能因工具版本过旧而报错；推动所有环境（及 AI 沙箱）同步更新二进制文件的成本极高。
  - **解析脆弱性**：CLI 的文字排版一旦为了人类阅读舒服改了一丁点（如加个空格、改个对齐），AI 里的 MCP 插件就可能解析失效，向后兼容性极差。
  - **Token 浪费与性能开销**：每次调用都要启动新进程，终端表格等装饰性字符会占用大量昂贵的上下文窗口。

### 2. 方案 B：让 AI 调用 RESTful API (推荐方式)

**实现逻辑**：MCP 作为一个“API 代理”，直接构造 HTTP 请求发送给后端。

- **优势 (Pros)**：
  - **数据原生性 (Native JSON)**：JSON 是 AI 的“母语”。没有排版干扰，没有幻觉，解析成功率 100%。
  - **服务端版本对齐 (Server Alignment)**：后端一升级，AI 看到的工具立刻同步增强，无需分发安装包，版本演进（如 `/v1`, `/v2`）非常平滑。
  - **Schema 稳定性**：JSON 结构天然支持向后兼容地增加字段，AI 会自动忽略未知字段，不会因为加了一列就崩溃。
  - **无状态与高并发**：API 交互天生是无状态的，不存在交互式输入挂起的问题，执行效率极高。
  - **全链路受益**：为了 AI 而进行的 API 规范化，会让前端开发（TS 类型生成）和后端健壮性同步提升。

- **劣势 (Cons)**：
  - **初期“还债”成本 (API Cleanup)**：由于当前 API 存在大量 `any` 类型返回值及不规范路径（如 `POST /create`），需要花费显性时间进行重构和 Swagger 整理，否则 AI 无法精准感知参数定义。
  - **认证逻辑重写 (Auth Mirroring)**：MCP 必须“手动”去读取 CLI 的配置文件，提取 Token 并注入 Header，存在小规模的逻辑重复。
  - **逻辑重复风险**：如果某些复杂逻辑（如数据预处理）只写在了 CLI 客户端里而没在后端，AI 就无法享受到这些功能，除非在后端或 MCP 中重写。

---

### 总结建议：如何决策？

1.  **如果你打算把逻辑写在 CLI 客户端**：
    那么让 AI 使用 **CLI** 增量成本最低。
    *   **代价**：你必须保证 CLI 所有的命令都有 `--json`、支持 `--non-interactive`，且需频繁维护二进制更新。

2.  **如果你打算把逻辑写在 Backend (推荐)**：
    那么让 AI 使用 **API** 效果最好。
    *   **代价**：你需要花费 2-3 天时间清理后端的 `any` 类型返回值。这不仅让 AI 变精准，还直接解决了前端 TS 类型自动生成的痛点。

**最终方案建议：**
- **人类**：通过 `crater-cli` 交互（体验好、带颜色、带确认）。
- **AI**：通过 **MCP 直连 API**（数据准、速度快、受规范 Schema 保护）。
- **纽带**：两者共享 `~/.crater/config` 配置文件，实现“一次登录，处处通行”。
